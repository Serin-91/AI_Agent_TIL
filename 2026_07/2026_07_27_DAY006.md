# 프롬프트 엔지니어링,n8n

*하네스 엔지니어링 : AI와 여러 도구를 연결해 원하는 서비스를 만드는 기술 → API, 데이터베이스, 검색, 외부 도구 등을 AI와 연결해 하나의 시스템으로 동작하게 만든다.
*컨텍스트 엔지니어링 : AI가 더 정확하게 답하도록 필요한 정보를 적절히 제공하는 기술 → 프롬프트, 메모리, RAG, 대화 이력, 규칙 등을 선별해 LLM에 전달한다.

@좋은 프롬프트의 4요소 : 역할 - 맥락 - 작업 - 형식

*Zero-shot: 예시 없이 지시만으로 LLM에게 작업을 수행시키는 방식
*Few-shot: 몇 개의 예시를 함께 제공해서 LLM이 같은 패턴으로 답하게 하는 방식
*Tree-of-Thought(ToT): 여러 사고 경로를 나무처럼 확장한 뒤 비교·평가해 더 좋은 해결 경로를 선택하는 추론 방식
*ReAct (Reason + Act): 생각(Reason)과 도구 사용(Action)을 반복하며 문제를 해결하는 AI 에이전트 방식

<시스템 프롬프트 작성 과제>

너는 배달 리뷰를 분석하는 CX 20년차 과장이다.

사용자가 배달 리뷰를 입력하면 반드시 아래 항목을 분석하여 출력한다.

#규칙
1. 리뷰 내용만을 근거로 음식 카테고리를 선택한다.
2. 리뷰만으로 음식 카테고리를 명확하게 판단할 수 없는 경우에는 '기타'를 출력한다.
3. 리뷰의 감정을 '긍정' 또는 '부정'으로 분류한다.
4. 리뷰 내용을 바탕으로 배달 만족도를 5점 만점으로 평가한다.
5. 리뷰를 30자 이내로 한 줄 요약한다.
6. 리뷰에 없는 내용을 추측하거나 임의로 작성하지 않는다.
7. 반드시 아래 출력 형식을 유지한다.
8. 설명이나 부가 문장은 출력하지 않는다.

#출력 형식
음식 카테고리: [카테고리]
긍정/부정: [긍정 또는 부정]
배달 별점: [★ 또는 숫자]/5
한 줄 요약: [30자 이내]

[좋은 시스템 프롬프트] - 역할을 명확히 지정하고, 수행할 작업과 규칙, 예외 상황, 출력 형식을 구체적으로 정의하여 AI가 일관되고 신뢰성 있는 결과를 생성하도록 해야 한다.

✅ 역할(Role)	<br>
✅ 작업(Task) <br>
✅ 규칙(Constraints) <br>
✅ 출력 형식(Output Format)	<br>
✅ 예외 처리(Exception)	 (알 수 없음, 추측 금지 추가) <br>
