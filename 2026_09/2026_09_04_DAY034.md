# RAG Evaluation

RAG 시스템의 **검색 성능과 생성된 답변 품질을 평가하는 방법**을 학습했다.

## Evaluation Flow

```text
Question
   ↓
Retrieval
   ↓
Retrieval Evaluation
   ↓
Answer Generation
   ↓
Citation Validation
   ↓
Answer Quality Evaluation
```

## Retrieval Metrics

* `Hit@k`: 상위 k개 결과 안에 정답이 존재하는지 평가
* `Precision@k`: 검색 결과 중 관련 결과의 비율 평가
* `Recall@k`: 필요한 정답을 얼마나 검색했는지 평가
* `MRR`: 정답이 검색 결과의 얼마나 높은 순위에 등장했는지 평가

검색 지표는 정답 문서와 검색 순위만으로 계산할 수 있어 LLM 호출이 필요하지 않는다.

## Citation & Answer Evaluation

* `valid_citation`: 실제 검색된 문서를 출처로 사용했는지 확인
* `relevant_citation`: 정답과 관련된 문서를 출처로 사용했는지 확인
* RAGAS
* LLM-as-Judge

## Public Document RAG Evaluation

Similarity Search와 MMR을 비교하고 다음 지표를 확인했다.

* File Hit@k
* Page Hit@k
* MRR

### File Hit vs Page Hit

* **File Hit**: 정답이 포함된 PDF 파일 검색 여부
* **Page Hit**: PDF 내부의 정답 페이지까지 정확하게 검색했는지 여부

실패 문항에서는 정답 파일은 검색했지만 다른 페이지를 가져오는 경우와, 같은 페이지의 여러 청크가 반복 검색되는 경우를 확인했다.

### Search Strategy Result

전체 성능은 Similarity와 MMR이 비슷했지만 `Page Hit@5` 실패 문항은 다음과 같았다.

* Similarity: 3건
* MMR: 2건

이번 실습 데이터에서는 MMR이 정답 페이지 검색에서 조금 더 좋은 결과를 보였다.

## Possible Improvements

검색 성능 개선을 위해 다음 설정을 조정해 비교할 수 있다.

* `chunk_size`
* `chunk_overlap`
* `k`
* MMR `fetch_k`
* MMR `lambda_mult`

`k`를 증가시키면 필요한 근거가 포함될 가능성이 높아질 수 있지만, 불필요한 문맥과 처리 비용도 증가할 수 있다.

## Key Point

검색 평가를 답변 평가보다 먼저 수행하면 **검색 단계의 실패와 LLM 답변 생성 단계의 실패를 구분할 수 있다.**

> 이번 실습은 PDF 문서를 벡터 검색 대상으로 구성한 뒤, Similarity Search와 MMR 중 어떤 방식이 정답 페이지를 더 잘 검색하는지 비교한 실습이다.
