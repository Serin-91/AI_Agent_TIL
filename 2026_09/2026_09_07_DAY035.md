# RAG Experiment Design

RAG 파이프라인의 설정값을 변경하면서 검색 성능, 생성 품질, 실행 시간 등의 차이를 비교하는 실험 구조를 학습했다.

## Dataset

- Hugging Face: `allganize/RAG-Evaluation-Dataset-KO`
- https://huggingface.co/datasets/allganize/RAG-Evaluation-Dataset-KO

## Experiment Inputs

실험 조건을 config로 분리하여 코드를 수정하지 않고 반복 테스트할 수 있도록 구성한다.

- Document path
- Evaluation dataset path
- `chunk_size`
- `chunk_overlap`
- Embedding model
- Retrieval strategy
- `k`
- `fetch_k`
- `lambda_mult`
- `weights`
- `context_k`
- Prompt path
- Generation model
- Evaluation model
- Generation evaluation metrics

## Output Files

### `summary.json`

실험 전체의 평균 평가 결과를 저장한다.

예:
- Precision
- Recall
- MRR
- Latency
- Generation evaluation
- Judge evaluation

### `config.snapshot.yaml`

해당 결과가 어떤 실험 설정으로 생성되었는지 기록한다.

```yaml
retrieval:
  strategy: Similarity
  top_k: 5
```

### `retrieval_results.csv`

평가 질문별 Retrieval 결과를 저장한다.

- Hit
- Precision
- Recall
- Latency

### `generation_results.csv`

LLM 생성 결과 및 Citation 검증 결과를 저장한다.

- Answer
- Citation
- `valid_citation`
- `relevant_citation`
- Latency

### `judge_results.csv`

LLM Judge 평가 결과를 저장한다.

- Correctness
- Completeness
- Groundedness
- Citation Accuracy

## Experiment Flow

```text
Config
  ↓
RAG Evaluation Script
  ↓
Retrieval
  ↓
Generation
  ↓
Evaluation
  ↓
Output
  ↓
Compare Experiments
```

예를 들어 Re-ranking 적용 전후, Chunk Size, Retrieval Strategy, `k` 등을 변경하고 성능과 Latency 등의 Trade-off를 비교한다.

핵심은 **실험마다 코드를 수정하는 것이 아니라 Config의 Input을 변경하여 동일한 Evaluation Script를 반복 사용하는 것**이다.
