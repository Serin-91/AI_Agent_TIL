# RAG & Advanced Retrieval

## RAG Pipeline

RAG는 크게 **인덱싱(Indexing)** 과 **질의(Query)** 단계로 구성된다.

### Indexing

```text
Load → Split → Embed → Vector DB
```

- **Load**: 문서 로딩
- **Split**: 문서를 적절한 크기의 Chunk로 분할
- **Embedding**: 텍스트를 의미 기반 벡터로 변환
- **Vector DB**: 임베딩 벡터와 문서 정보 저장

### Query

```text
Question → Retrieval → Context → LLM → Answer
```

질문과 의미적으로 가까운 문서를 검색한 후 해당 문서를 LLM의 Context로 사용한다.

---

## Vector Database

벡터 공간에서 텍스트의 의미를 벡터로 저장하고 유사도를 기반으로 검색한다.

대표적인 도구:

- Chroma
- pgvector
- FAISS
- Pinecone

### Metadata

문서의 source, category, page 등의 부가 정보를 저장하며 검색 범위를 제한하는 데 사용할 수 있다.

## Advanced Retrieval

검색 전략을 변경하기 전에 문서 및 Chunk의 데이터 품질을 먼저 확인하는 것이 중요하다.

| Method | Description |
|---|---|
| MMR | 관련성과 검색 결과의 다양성을 함께 고려 |
| BM25 | 질문과 문서의 키워드 일치도를 기반으로 검색 |
| Hybrid Search | Vector Search와 BM25를 결합 |
| Re-ranking | 검색된 후보 문서를 다시 평가하여 관련도 순으로 재정렬 |

```text
Vector Search = Semantic Search
BM25         = Keyword Search
Hybrid       = Vector + BM25
Re-ranking   = Candidate Reordering
```
