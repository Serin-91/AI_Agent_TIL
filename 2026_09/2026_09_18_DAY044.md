# Multi-Agent Practice

LangGraph 기반의 범용 기획 Multi-Agent 구조를 실습했다.

Supervisor가 사용자 요청을 분석해 필요한 Agent를 선택하고, 복합 요청에서는 각 Agent의 결과를 다음 Agent의 입력으로 연결한다.

## Architecture

```text
User
 ↓
Supervisor
 ├─ Research Agent
 ├─ Planning Agent
 └─ Review Agent
 ↓
Final Response
```

### Supervisor

상위 orchestration을 담당한다.

- 사용자 요청 분석
- 필요한 Agent 선택
- 실행 순서 결정
- Agent 간 결과 전달
- 최종 결과 종합

별도의 Router 및 상위 conditional edge는 사용하지 않는다.

## Agents

### Research Agent

**Orchestrator-Worker** 패턴을 사용한다.

```text
Request
 ↓
Orchestrator
 ↓
Research Items
 ↓
Send
 ↓
Workers
 ↓
Research Results
 ↓
Final Research
```

State:

```text
request
research_items
research_results
final_research
```

### Planning Agent

**Plan-and-Execute Lite** 구조를 사용한다.

```text
Input
 ↓
Plan
 ↓
Step-by-step Execution
 ↓
Final Plan
```

State:

```text
input
plan
past_steps
response
```

이번 실습에서는 Replanner를 생략했다.

### Review Agent

**Evaluator-Optimizer** 패턴을 사용한다.

```text
Plan
 ↓
Evaluator
 ↓
PASS / REVISE
       ↓
    Optimizer
       ↓
  Revised Plan
       ↓
   Re-evaluate
```

State:

```text
plan
feedback
status
revised_plan
review_count
```

무한 반복을 방지하기 위해 최대 review 횟수를 제한한다.

## Multi-Agent Flow

복합 요청의 예:

```text
User
 ↓
Supervisor
 ↓
Research Agent
 ↓
final_research
 ↓
Supervisor
 ↓
Planning Agent
 ↓
final_plan
 ↓
Supervisor
 ↓
Review Agent
 ↓
revised_plan
 ↓
Supervisor
 ↓
Final Response
```

Agent 간 결과는 직접 전달하지 않고, Supervisor가 이전 Agent의 결과를 다음 Agent 호출 입력에 포함한다.

## Memory

최상위 Supervisor에 Checkpointer를 연결하며 `main.py`에서 동일한 `thread_id`를 유지한다.

이를 통해 후속 대화에서도 이전 조건과 작업 흐름을 이어갈 수 있다.

## Project Structure

```text
multi-agent-practice/
│
├── PRACTICE.md
├── HINT.md
│
└── src/
    ├── main.py
    ├── graph.py
    └── agents/
        ├── planning.py
        ├── review.py
        └── research/
            ├── __init__.py
            ├── prompts.py
            ├── nodes.py
            └── graph.py
```

### `main.py`

- 사용자 입력 반복
- 종료 명령 처리
- 동일한 `thread_id` 유지
- Supervisor 실행
- 최종 답변 출력

### `graph.py`

- Research / Planning / Review Agent를 Tool로 구성
- Supervisor 생성
- Agent Tool 등록
- Checkpointer 연결

### `planning.py`

- `PlanningState`
- 계획 생성
- 단계별 작성
- 최종 plan 반환

### `review.py`

- `ReviewState`
- Evaluator
- Optimizer
- PASS / REVISE
- 최대 반복 제한

### `research/`

Orchestrator-Worker 기반 Research Agent를 구성한다.

- `prompts.py`: 조사 항목 / Worker / 결과 종합 Prompt
- `nodes.py`: ResearchState, Orchestrator, Worker, 결과 종합 Node
- `graph.py`: StateGraph, Send 기반 병렬 실행, compile

## Key Points

| Item | Structure |
|---|---|
| Top-level orchestration | Supervisor |
| Router | Not used |
| Top-level conditional edge | Not used |
| Research | Orchestrator-Worker |
| Planning | Plan-and-Execute Lite |
| Replanner | Omitted |
| Review | Evaluator-Optimizer |
| Memory | Supervisor Checkpointer |
| Conversation continuity | Same `thread_id` |
| Agent data transfer | Via Supervisor |
| External search | Optional / not used currently |

외부 검색을 사용하지 않은 정보는 임의로 사실처럼 생성하지 않고 필요한 경우 `가정`임을 명시한다.

또한 실행 결과에서 **실제로 호출된 Agent 이름과 호출 순서**를 확인할 수 있도록 구성한다.

## Goal

사용자 요청에 따라 필요한 Agent만 선택하고, 복합 요청에서는 이전 Agent의 결과를 다음 Agent가 활용하며, 후속 대화에서도 앞선 조건과 계획을 기억하는 범용 기획 Multi-Agent 시스템을 구현하는 것이 목표이다.
