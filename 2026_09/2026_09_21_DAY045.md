# Fault Tolerance & Agent Tool Control

## Fault Tolerance

Agent 실행 중 장애가 발생해도 전체 작업을 처음부터 다시 실행하지 않고 복구할 수 있도록 설계하는 방식이다.

### RetryPolicy

- 실패한 노드만 자동 재시도
- 재시도 횟수 소진 여부 처리
- 재시도 가능한 오류와 불가능한 오류 구분

```text
Node 실행
   ↓
실패
   ↓
RetryPolicy
   ↓
재실행
```

### Checkpoint

`checkpoint`와 `thread_id`를 이용해 실행 상태를 저장하고 실패 지점부터 작업을 재개할 수 있다.

- 순차 실행: 실패한 지점부터 재개
- 병렬 실행: 성공한 branch의 결과는 유지하고 실패한 branch만 재실행

### Timeout & Error Handling

- `TimeoutPolicy`: 노드 실행 시간 제한
- 재시도까지 실패한 경우 `error_handler`와 `Command`를 이용해 실패 상태 처리
- `set_node_defaults()`를 이용한 공통 노드 정책 관리

### Idempotency

외부 저장이나 API 요청이 재시도될 때 동일한 작업이 중복 처리되지 않도록 멱등성을 고려한다.

```text
동일 요청 재실행
→ 이미 처리된 요청인지 확인
→ 중복 저장 방지
```

# Agent Tool Control

Agent의 Tool 실행을 LLM의 판단에만 맡기지 않고 프로그램에서 검사하고 통제한다.

## Middleware

```python
@wrap_model_call
@wrap_tool_call
```

Middleware를 이용해 Model 또는 Tool 실행 과정에 개입할 수 있다.

### Tool 실행 전

- 인자 검사
- 권한 검사
- 승인 여부 확인
- 조건 통과 후 `handler(request)` 실행

### Tool 실행 후

- Tool 반환값 검증
- 비정상 결과에 대한 후속 처리

### Context

Context는 LLM이 생성한 값이 아니라 프로그램이 Agent에게 전달하는 실제 권한 및 실행 기준이다.

```text
LLM의 Tool 요청
      ↓
Middleware
      ↓
Context 기반 권한 검사
      ↓
허용 / 차단
```

**핵심:** Tool 실행 여부를 LLM에게 전적으로 맡기지 않고 Middleware와 Context를 통해 프로그램에서 통제한다.

# LangGraph Logging

`print()` 대신 `logging`을 사용해 Agent 실행 상태와 오류를 기록한다.

```python
logging.info("노드 실행")
logging.error("Tool 실행 실패")
```

Logging을 통해 다음 정보를 추적할 수 있다.

- 노드 실행 상태
- 성공/실패 위치
- 오류 발생 지점
- Agent 전체 실행 흐름

## Summary

```text
Fault Tolerance → 실패 후 복구
Tool Control    → Tool 실행 통제
Logging         → 실행 과정 추적
```
