# Plan-and-Execute

복잡한 요청을 바로 처리하지 않고, **먼저 전체 계획을 세운 뒤 각 단계를 하나씩 실행하는 Agent 패턴**이다.

## Flow

```text
User Request
   ↓
Planner
   ↓
Executor
   ↓
Execution Result
   ↓
Replanner
   ↓
Executor
   ↓
...
   ↓
Final Response
```

- **Planner**: 전체 작업 계획 생성
- **Executor**: 계획을 하나씩 실행
- **Replanner**: 실행 결과를 바탕으로 남은 계획을 수정하거나 종료 판단

## Replanner

### With Replanner

실행 결과에 따라 계획을 중간에 수정할 수 있어 유연하다.

### Without Replanner

처음 생성한 계획을 그대로 순서대로 실행한다. 구조가 단순하고 구현하기 쉽다.

## State

| State | 역할 |
|---|---|
| `input` | 사용자의 원래 요청 |
| `plan` | 앞으로 실행해야 할 작업 |
| `past_steps` | 지금까지 실행한 작업과 결과 |
| `response` | 최종 사용자 응답 |

핵심적으로 Agent가 기억해야 하는 것은 다음 네 가지다.

```text
원래 요청
→ 앞으로 할 일
→ 이미 한 일
→ 최종 답변
```

**Plan-and-Execute의 핵심은 계획을 State에 저장하고, 실행 결과를 누적하면서 최종 목표까지 단계적으로 수행하는 것이다.**
