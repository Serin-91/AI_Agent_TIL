# Parallelization & Orchestrator-Worker

## Parallelization

LangGraph에서 서로 의존하지 않는 여러 노드를 동시에 실행하는 방식이다.

- 독립적인 작업을 병렬 처리
- 순차 실행보다 전체 처리 시간을 줄일 수 있음

### Voting Pattern

하나의 질문에 대해 여러 LLM 응답을 병렬로 생성한 뒤, 결과를 비교하여 가장 좋은 답변을 선택하는 패턴이다.

```text
Question
   ↓
Multiple LLM Responses
   ↓
Evaluation
   ↓
Best Response
```

## Orchestrator-Worker

복잡한 요청을 여러 작업으로 분해하고, 필요한 Worker들을 동적으로 병렬 실행한 뒤 결과를 통합하는 패턴이다.

- **Orchestrator**: 요청을 분석하고 필요한 작업을 분해
- **Worker**: 분해된 개별 작업 수행
- **Send**: 필요한 작업 수만큼 Worker 실행
- **Dynamic Fan-out**: Worker 개수를 실행 중 동적으로 결정
- **Parallel Execution**: 여러 Worker를 동시에 실행
- **Reducer**: 여러 Worker의 결과를 하나의 State에 누적

```text
User Request
     ↓
Orchestrator
     ↓
Task Decomposition
     ↓
Send
     ↓
Worker 1 ─┐
Worker 2 ─┼─ Parallel
Worker 3 ─┘
     ↓
Reducer
     ↓
Combined Result
```

## 핵심 차이

- **Parallelization**: 이미 정해진 여러 작업을 동시에 실행
- **Orchestrator-Worker**: 입력을 먼저 분석하고 작업의 종류와 개수를 동적으로 결정한 뒤 병렬 실행
