# FastAPI + SQLAlchemy 쇼핑몰 백엔드 구현

**Date:** 2026-10-27  
**Topic:** Database Relationships, SQLAlchemy ORM, Layered Architecture, Transactions

## 1. 학습 개요

FastAPI와 SQLAlchemy를 활용한 쇼핑몰 백엔드 구조를 학습하고, 데이터베이스 관계 설정과 계층별 역할 분리를 정리했다.

### 핵심 학습 내용

- 1:N 관계: 상품과 리뷰
- N:M 관계: 상품과 기획전
- SQLAlchemy ORM 기반 DB 처리
- Router / Service / Repository 계층 분리
- DB 트랜잭션 관리

## 2. 데이터베이스 관계

### 1:N (One-to-Many)

하나의 상품에 여러 리뷰가 연결되는 관계.

```text
Product (1) ──── (N) Review
```

- `ForeignKey()`로 테이블 간 참조 관계 설정
- `relationship()`으로 ORM 객체 간 관계 탐색

### N:M (Many-to-Many)

여러 상품과 여러 기획전이 연결되는 관계.

```text
Product (1)
    │
    ▼ (N)
ProductCollection
    ▲ (N)
    │
Collection (1)
```

- `ProductCollection` 중간 테이블 활용
- `association_proxy()`로 연결 객체 접근 간소화

## 3. SQLAlchemy ORM

SQL을 직접 작성하는 대신 Python 클래스와 객체를 활용하여 데이터베이스 작업을 처리한다.

```python
products = db.query(Product).all()
```

### 주요 문법

| 문법 | 역할 |
|---|---|
| `ForeignKey()` | 외래 키 정의 |
| `relationship()` | ORM 객체 관계 설정 |
| `association_proxy()` | 중간 관계 접근 간소화 |
| `Depends(get_db)` | DB 세션 의존성 주입 |
| `with db.begin()` | 트랜잭션 관리 |
| `HTTPException()` | HTTP 오류 응답 |

## 4. 레이어드 아키텍처

```text
Client
  ↓
Router
  ↓
Service
  ↓
Repository
  ↓
Database
```

| Layer | Responsibility |
|---|---|
| Router | HTTP 요청 및 응답 처리 |
| Service | 비즈니스 로직 처리 |
| Repository | DB 조회·저장·수정·삭제 |
| Database | 데이터 저장 및 관리 |

역할별 계층 분리를 통해 유지보수성과 코드 재사용성을 높이는 구조를 학습했다.

## 5. 트랜잭션

여러 DB 작업을 하나의 작업 단위로 처리한다.

```python
with db.begin():
    # Database operations
    ...
```

- COMMIT: 변경 사항 확정
- ROLLBACK: 오류 발생 시 트랜잭션 변경 사항 취소

## 6. 핵심 정리

- **1:N / N:M 관계**를 통해 데이터 간 연결 구조 이해
- **SQLAlchemy ORM**으로 Python 기반 DB 작업 수행
- **Router → Service → Repository** 구조로 책임 분리
- **Transaction**으로 여러 DB 작업의 일관성 관리
