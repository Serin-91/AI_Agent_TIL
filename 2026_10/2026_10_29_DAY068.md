**Date:** 2026-10-29

## 3. Async FastAPI & SQLAlchemy

### async/await

I/O 작업 대기 중 다른 요청을 처리할 수 있는 비동기 구조.

```python
# SQLAlchemy AsyncSession 예시
db.add(product)

await db.flush()
await db.commit()
```

- `db.add()` : 세션에 객체 등록
- `flush()` : 변경 사항을 DB에 전달
- `commit()` : 트랜잭션 확정
- `rollback()` : 트랜잭션 변경 취소

### AsyncSession 관리

- 요청별 DB 세션 생성 및 종료
- 동시 요청 간 AsyncSession 공유 금지
- 관계 데이터 Eager Loading으로 암묵적 DB I/O 방지
- `MissingGreenlet` 오류 주의

## 4. Alembic Migration

SQLAlchemy 모델의 DB 스키마 변경 이력을 관리한다.

```bash
# Revision 생성
alembic revision --autogenerate -m "update schema"

# 최신 변경 적용
alembic upgrade head
```

자동 생성된 마이그레이션 파일은 적용 전에 검토해야 한다.

## 7. RAG Workflow

Chroma에 저장된 문서를 검색하고 LLM이 검색 결과를 참고해 답변하는 고정형 RAG 구조.

```text
User Query
    ↓
Chroma Retrieval
    ↓
Relevant Documents
    ↓
LLM Generation
    ↓
Response
```

### 고정형 RAG의 특징

- 검색 단계 고정
- 예측 가능한 실행 흐름
- 테스트 및 디버깅 용이

### 주요 주의사항

- Chunk 분할 품질
- 검색 결과의 관련성
- 답변과 검색 근거의 일치 여부
- 실습의 문서 재적재 시 Chroma 컬렉션 삭제

## 8. LangGraph Streaming

### ainvoke() vs astream()

| Method | Description |
|---|---|
| `ainvoke()` | 비동기 실행 후 최종 결과 반환 |
| `astream()` | 실행 중 데이터를 스트리밍 |

### SSE Events

| Event | Purpose |
|---|---|
| `status` | 실행 상태 |
| `sources` | 검색 출처 |
| `token` | 답변 내용 |
| `done` | 정상 완료 |
| `error` | 실행 오류 |

### Completion Rule

```text
LLM Generation
      ↓
SSE Token Streaming
      ↓
Conversation Persistence
      ↓
DB Commit Success
      ↓
SSE done
```

화면에 답변이 표시되어도 DB 저장이 실패했다면 정상 완료로 처리하지 않는다.

## 9. Multi-turn Conversation & Checkpointer

PostgreSQL 기반 Checkpointer로 LangGraph의 대화 상태를 저장·복원한다.

| Key | Purpose |
|---|---|
| `thread_id` | 대화 흐름 식별 |
| `checkpoint_id` | 특정 저장 시점 식별 |

```text
thread_id
    │
    ├── checkpoint_id_1
    ├── checkpoint_id_2
    └── checkpoint_id_3
```

동일한 `thread_id`를 사용해 저장된 대화 상태를 복원한다.

정상적으로 영속 저장된 체크포인트는 서버 재시작 후에도 활용할 수 있다.

## 10. Concurrency Control

동일 채팅방의 중복 요청으로 인한 상태 충돌을 방지한다.

### FOR UPDATE NOWAIT

- PostgreSQL 행 잠금 활용
- 잠금 충돌 시 즉시 오류 발생
- 애플리케이션에서 충돌을 `409 CHAT_ROOM_BUSY`로 변환
- Fail-fast 방식의 동시 요청 제어

```text
Question A Processing
         │
         └── Question B Request
                    │
                    ▼
              Lock Conflict
                    │
                    ▼
             409 CHAT_ROOM_BUSY
```

트랜잭션 잠금의 유지 범위와 AI 요청 처리 범위를 고려하여 설계해야 한다.
