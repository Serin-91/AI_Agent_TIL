## 3. JWT Authentication

로그인 성공 시 JWT를 발급하고, 인증이 필요한 API 요청에서 토큰을 검증하여 사용자를 식별한다.

### JWT 설정

| 항목 | 값 |
|---|---|
| Algorithm | HS256 |
| Expiration | 30분 |
| `sub` | 사용자 ID |
| `iat` | 발급 시각 |
| `exp` | 만료 시각 |

### 주요 함수

```python
# 비밀번호 해싱
hash_password(password)

# 비밀번호 검증
verify_password(password, hashed_password)

# JWT 생성
create_access_token(user_id)

# JWT 검증 및 사용자 정보 추출
decode_access_token(token)
```

### 인증 흐름

```text
Login
  ↓
JWT Issuance
  ↓
Authenticated API Request
  ↓
JWT Validation
  ↓
Current User Identification
```

JWT는 서명과 만료 여부 등을 검증한 뒤 인증에 활용한다.

## 4. Authentication vs Authorization

| 구분 | Authentication | Authorization |
|---|---|---|
| 목적 | 사용자 신원 확인 | 접근·작업 권한 검사 |
| 질문 | 누구인가? | 권한이 있는가? |
| 구현 예시 | JWT 사용자 인증 | 위시리스트 소유자 확인 |

### 위시리스트 권한 검사

- 로그인 사용자 식별
- 삭제 대상 위시리스트의 소유자 확인
- 본인 데이터가 아닌 경우 `403 Forbidden` 반환

## 6. Layered Architecture

```text
Client
  ↓
Router
  ↓
Service
  ↓
Repository
  ↓
Database
```

### 주요 파일 및 역할

| File | Responsibility |
|---|---|
| `auth_router.py` | 회원가입·로그인 API |
| `auth_service.py` | 회원가입·로그인 비즈니스 로직 |
| `user_repository.py` | 사용자 DB 조회·저장 |
| `security.py` | 비밀번호 해싱·JWT 처리 |
| `dependencies.py` | 현재 로그인 사용자 확인 |
| `wishlist_service.py` | 위시리스트 비즈니스 로직 |

기존 Router → Service → Repository 계층 구조를 유지하면서 인증 및 보안 관련 책임을 분리했다.

4. **Layered Architecture:** 인증·비즈니스 로직·DB 접근 책임 분리
