# 📚 32｜PostgreSQL을 활용한 AI Agent

## 학습 목표

PostgreSQL에 저장된 데이터를 AI Agent가 안전하게 조회할 수 있도록 DB 권한 관리, SQL Tool, Text-to-SQL, SQL 검증 및 LangGraph 실행 제어 구조 학습.

## 1. PostgreSQL 권한 관리

DCL을 활용해 Agent 전용 DB 계정을 생성하고 필요한 조회 권한을 부여한다.

```sql
CREATE ROLE agent_reader LOGIN PASSWORD 'YOUR_AGENT_PASSWORD';

GRANT CONNECT ON DATABASE world TO agent_reader;

GRANT USAGE ON SCHEMA public TO agent_reader;

GRANT SELECT ON country, city, countrylanguage
TO agent_reader;
```

- `GRANT`: 권한 부여
- `REVOKE`: 권한 회수
- `SELECT`: 데이터 조회 권한
- 최소 권한 원칙을 적용한 Agent 계정 구성

## 2. Python과 PostgreSQL 연결

사용 기술:

- `python-dotenv`: 환경변수 로딩
- `os.getenv()`: DB 설정 조회
- `psycopg`: PostgreSQL 연결 및 SQL 실행
- `dict_row`: 딕셔너리 형태 결과 반환

```python
from dotenv import load_dotenv
import os
import psycopg

load_dotenv()

conn = psycopg.connect(
    host="localhost",
    dbname=os.getenv("AGENT_POSTGRES_DB"),
    user=os.getenv("AGENT_POSTGRES_USER"),
    password=os.getenv("AGENT_POSTGRES_PASSWORD")
)
```

DB 연결 정보는 `.env`로 분리하며, 민감 정보는 저장소에 포함하지 않는다.

## 3. SQL 조회

주요 SQL 문법:

| SQL | 역할 |
|---|---|
| `SELECT` | 데이터 조회 |
| `WHERE` | 조건 필터링 |
| `JOIN` | 테이블 연결 |
| `GROUP BY` | 그룹화 |
| `ORDER BY` | 정렬 |
| `LIMIT` | 결과 제한 |
| `ILIKE` | 대소문자 구분 없는 문자열 검색 |
| `SUM()` / `COUNT()` | 집계 |

`%s` 파라미터 바인딩을 활용해 SQL에 값을 전달한다.

## 4. 고정 SQL Tool Agent

개발자가 SQL을 미리 정의하고 LLM이 질문에 맞는 Tool과 인자를 선택하는 방식.

- `@tool`: Python 함수 Tool 등록
- `search_countries`: 국가 검색
- `get_country_cities`: 국가별 도시 조회
- `create_agent()`: LLM과 Tool 연결

```text
사용자 질문
    ↓
LLM Tool 선택
    ↓
고정 SQL 실행
    ↓
PostgreSQL 조회
    ↓
결과 기반 답변
```

## 5. Text-to-SQL

자연어 질문을 LLM이 SQL로 변환하는 방식.

- `SQLDatabase`: 데이터베이스 구조 활용
- `get_table_info()`: 테이블 정보 조회
- `include_tables`: 제공할 스키마 범위 제한
- `with_structured_output()`: 구조화된 SQL 출력

```text
자연어 질문
    ↓
DB 스키마 확인
    ↓
LLM SQL 생성
    ↓
SQL 검증
    ↓
DB 실행
    ↓
결과 기반 답변
```

## 6. SQLGlot 안전성 검사

`validate_sql()`을 통한 SQL 실행 전 검증.

- 단일 SELECT 문만 허용
- INSERT / UPDATE / DELETE 등 변경 명령 차단
- 다중 SQL 문 검사
- 내부 위험 구문 검사

안전성 확보를 위한 구성:

1. SQLGlot 기반 구문 검증
2. DB 계정 최소 권한
3. 읽기 전용 트랜잭션

## 7. LangGraph SQL Agent

### 주요 State

- 사용자 질문
- 데이터베이스 스키마
- 생성 SQL
- 조회 결과
- 오류 정보
- 시도 횟수
- 최종 답변

### 주요 Node

| Node | 역할 |
|---|---|
| `load_schema` | 스키마 로딩 |
| `generate_sql` | SQL 생성 |
| `execute_sql` | SQL 검증 및 실행 |
| `route_result` | 실행 결과에 따른 분기 |
| `answer` | 최종 답변 생성 |

```text
START
  ↓
load_schema
  ↓
generate_sql
  ↓
execute_sql
  ↓
route_result
  ├── 성공 → answer → END
  └── 실패 → generate_sql 재시도
```

최초 생성을 포함해 최대 3회 SQL 실행 시도.

## 8. dvdrental Agent 실습

기존 `world` DB 기반 Agent를 영화 대여 데이터베이스에 적용.

**기본 실습**
- 영화·배우·카테고리 조회
- 고객 정보 접근 제한
- 데이터 변경 차단

**심화 실습**
- `customer_id=1`의 본인 대여 기록 조회
- 다른 고객의 대여 기록 접근 차단

실제 서비스에서는 인증된 사용자와 조회 권한을 연계하는 접근 제어가 필요하다.

## 핵심 정리

- DCL을 활용한 Agent 전용 DB 계정 및 권한 설정
- 고정 SQL Tool과 Text-to-SQL의 차이 이해
- SQLGlot 기반 SQL 검증
- PostgreSQL 최소 권한 및 읽기 전용 설정
- LangGraph를 활용한 SQL 생성·실행·오류 재시도 흐름 구성

**핵심:** LLM의 SQL 생성 능력과 실제 DB 실행 권한을 분리하여, 허용된 데이터만 안전하게 조회하는 AI Agent 구조를 학습했다.
