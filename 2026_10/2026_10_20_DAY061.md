# Financial Document RAG Agent & Evaluation

금융 PDF 문서를 기반으로 근거 중심의 한국어 답변을 생성하는 RAG Agent를 구현하고, 평가 루프를 통해 검색 및 답변 성능을 비교·개선하는 실습 프로젝트입니다.

## 1. Objectives

- PDF 페이지별 추출·청킹·임베딩
- 금융 문서 검색 도구 구현
- 출처 기반 한국어 답변 생성
- 근거 충분성 판단 및 Agent 분기 설계
- 직접 작성한 Golden Set 구축
- 검색·답변 품질 평가
- 청킹·검색 전략 비교
- Basic RAG vs RAG Agent 성능 비교
- 평가 결과 분석 및 개선

## 2. Dataset

| 데이터 | 개수 |
|---|---:|
| 금융용어집 | 1 PDF |
| 금융 표준약관 | 15 PDFs |
| 금융생활 가이드북 | 1 PDF |
| 추가 금융 문서 | 6 PDFs |
| **PDF 합계** | **23** |
| **평가 질문 합계** | **180** |

### Evaluation Sets

| Set | Case IDs | Count |
|---|---|---:|
| Basic Positive | POS001~POS060 | 60 |
| Basic Negative | NEG001~NEG040 | 40 |
| Life Guide Positive | POS061~POS080 | 20 |
| Additional Positive | ADD-* | 60 |

기본 평가 세트는 금융용어집과 표준약관을 대상으로 하며, 금융생활 가이드북 및 추가 문서 세트는 별도로 평가합니다.

## 3. Architecture

```text
Financial PDFs
    ↓
PDF Loader
    ↓
Text Chunking
    ↓
Embedding
    ↓
Vector Store
    ↓
Retriever
    ↓
Evidence Evaluation
    ↓
Agent Decision
    ├── Sufficient → Generate Answer
    ├── Insufficient → Rewrite Query / Retrieve
    └── Unanswerable → Clarify / Correct / Abstain / Refuse
    ↓
Answer with Citations
    ↓
Execution Logging
    ↓
Evaluation
```

## 4. Evaluation

### Retrieval Quality
- Recall@k
- Hit@k

### Answer Quality
- Answer Correctness
- Faithfulness
- Negative Handling Accuracy

### Efficiency
- Latency
- LLM Calls
- Retrieval Calls
- Input / Output Tokens

## 5. Experiments

| Experiment | Comparison |
|---|---|
| Chunking | Chunk size, overlap, structure-aware chunking |
| Retrieval | Vector, BM25, Hybrid |
| Architecture | Basic RAG vs RAG Agent |

각 실험은 Baseline을 기준으로 설정 변경 내역을 기록하며, 동일한 질문 세트와 문서 범위에서 비교합니다.

## 6. Evaluation Loop

```text
Define Baseline
      ↓
Run Evaluation Cases
      ↓
Save Outputs & Metrics
      ↓
Analyze Failures
      ↓
Modify Configuration
      ↓
Re-evaluate
      ↓
Compare Results
```

실패 유형은 Retrieval Failure와 Generation Failure로 구분합니다.

## 7. Experiment Tracking

주요 기록 항목:

- Experiment ID / Case ID
- Model & Prompt Version
- Chunking & Retrieval Configuration
- Retrieved Chunk IDs / Sources / Pages
- Generated Answer
- Evaluation Scores
- Execution Time
- Model / Retrieval Calls
- Token Usage
- Changes from Baseline

결과는 JSON 또는 DB에 저장하고 실험 ID를 기준으로 비교합니다.

## 9. Key Takeaway

This project focuses on building an evidence-grounded RAG Agent and establishing a reproducible evaluation loop.

The objective is to measure retrieval quality, answer correctness, grounding, and computational cost, then validate improvements through controlled experiments.
