# 📚 34｜PDF 텍스트·표·이미지 추출과 청킹

## 학습 목표

PDF에서 본문·표·이미지를 추출하고, 데이터의 구조와 의미를 유지하면서 RAG에 적합한 청크를 생성하는 방법 학습.

**핵심:** 표의 헤더·데이터 행·각주를 보존하는 Table-aware Chunking 구현 원리.

## 1. PDF 데이터 추출

| 도구 | 역할 |
|---|---|
| `PyPDFLoader` | PDF 본문 텍스트 추출 |
| `pdfplumber` | 표 구조 및 이미지 영역 탐색 |
| `Gemini` | 이미지 정보 추출 및 Markdown 변환 |

### 표 추출 및 정리

- `page.find_tables()`: 표 탐색
- `table.extract()`: 행·열 데이터 추출
- `bbox`: 표 위치 좌표 확인
- `normalize_cell()`: 셀 데이터 정리
- `markdown_row()`: Markdown 표 행 생성
- 병합 셀의 누락 값 보완 및 각주 유지

## 2. 유형별 데이터 처리

| content_type | 청킹 방식 |
|---|---|
| `text` | RecursiveCharacterTextSplitter |
| `table` | Table-aware Chunking |
| `image` | RecursiveCharacterTextSplitter |

- `build_page_blocks()`: 추출 결과를 원본 위치에 맞춰 블록화
- `document_blocks`: 유형별 블록 및 출처 정보 저장
- 표·이미지 영역의 중복 텍스트 제거

## 3. Table-aware Chunking

일반적인 길이 기준 청킹은 표의 헤더·행·각주를 분리할 수 있다.

**Table-aware Chunking은 행 단위로 분할하면서 헤더와 각주를 반복하여 데이터의 의미를 보존한다.**

### split_table_rows() 처리 흐름

```text
headers, footnotes 준비
    ↓
for row in rows
    ↓
다음 행 추가 시 chunk_size 초과 여부 확인
    ↓
초과하면 현재 행 묶음을 청크로 저장
    ↓
새 청크에 헤더·각주 포함
    ↓
마지막 남은 행 저장
```

주요 변수:
- `current_rows`: 현재 청크의 행 목록
- `parts`: 완성된 청크 목록
- `chunk_size`: 청크 길이 기준
- `headers`, `footnotes`: 반복하여 유지할 정보

단일 행은 중간에 분할하지 않으며, 필요한 경우 기준 길이를 초과하도록 허용한다.

### 청킹 비교 실습

표와 각주를 포함한 511자 데이터 사용.

| 방식 | 결과 |
|---|---|
| 일반 청킹 1,000자 | 표 전체 유지 |
| 일반 청킹 300자 | 표 구조 분리 문제 확인 |
| Table-aware 300자 | 행 단위 분할 및 헤더·각주 유지 |

## 4. Metadata 유지

`split_document_blocks()`에서 유형별 청킹을 적용하고 `table_aware_chunks` 생성.

주요 메타데이터:

- `page_no`: 원본 페이지
- `content_type`: 데이터 유형
- `block_id`: 원본 블록 ID
- `table_id`: 원본 표 ID
- `table_part`: 표 청크 순서
- `chunk_index`: 전체 청크 순서

## 5. RAG 파이프라인

```text
PDF 추출
    ↓
데이터 구조화
    ↓
유형별 청킹
    ↓
Metadata 유지
    ↓
임베딩
    ↓
벡터 DB
    ↓
검색
```

이번 학습은 임베딩 및 벡터 DB 구현 이전의 데이터 전처리 단계에 집중.

### 추가 학습 개념

- **Contextual Retrieval**: 청크에 관련 문맥 추가
- **표 요약 기반 검색**: 표 요약 검색 후 원본 표 활용
- **OCR**: 스캔 PDF의 문자 인식
- **PyMuPDF / Camelot**: 기타 PDF 처리 도구

## 핵심 정리

- PDF의 본문 추출과 표 구조 복원은 별도의 처리 문제다.
- 표 청킹에서는 헤더·행·각주의 관계를 유지해야 한다.
- `content_type`을 기반으로 데이터 유형별 청킹을 적용한다.
- Metadata를 통해 검색 결과의 출처를 추적한다.

**RAG 전처리의 핵심은 단순한 텍스트 분할이 아니라 정보의 구조와 의미를 보존하는 것이다.**
