# 웹 개발 기초 정리

## 1. 좋은 기획서의 공통점

* 성공 기준을 구체적인 숫자로 정의한다.
* 이번 프로젝트에서 만들지 않을 기능을 정한다.
* 사용자 요구와 기술 가능성을 먼저 조사한다.
* 구현 실패에 대비한 대체 계획을 준비한다.

---

## 2. 기본 CS 지식의 필요성

* AI 서비스를 만들려면 프론트엔드, 백엔드, 데이터베이스, API, 배포 구조를 함께 이해해야 한다.

---

## 3. 웹 렌더링 방식

### CSR

* 브라우저가 JavaScript를 실행해 화면을 만든다.
* 상호작용이 많은 화면에 적합하지만 초기 로딩과 SEO에 불리할 수 있다.

### SSR

* 사용자가 요청할 때 서버가 HTML을 생성한다.
* 최신 데이터와 SEO에 유리하지만 서버 부담이 커질 수 있다.

### SSG

* 배포 시 HTML을 미리 생성한다.
* 속도가 빠르지만 콘텐츠 변경 시 다시 생성해야 한다.

### ISR

* 미리 생성한 페이지를 일정 조건에 따라 부분 갱신한다.
* SSG의 속도와 콘텐츠 최신성을 함께 확보할 수 있다.

### 하이브리드 렌더링

* 페이지 목적에 따라 CSR, SSR, SSG, ISR을 조합한다.

---

## 4. 렌더링 방식 선택 기준

* 첫 화면 속도
* SEO 필요성
* 실시간 데이터 여부
* 사용자 개인화
* 화면 상호작용
* 서버 비용
* 콘텐츠 변경 주기

---

## 5. 렌더링 핵심 비교

* **CSR:** 브라우저에서 화면 생성
* **SSR:** 요청할 때 서버에서 화면 생성
* **SSG:** 배포할 때 화면 미리 생성
* **ISR:** 미리 생성한 화면을 부분 갱신
* **Hybrid:** 페이지별로 여러 방식 조합

---

## 6. SEO와 GEO

* **SEO:** 검색엔진이 웹페이지를 잘 이해하고 노출하도록 최적화하는 것
* **GEO:** 생성형 AI가 콘텐츠를 잘 이해하고 답변에 활용하도록 최적화하는 것

---

## 7. React, Next.js, Vercel

* **React:** 재사용 가능한 컴포넌트로 UI를 만드는 JavaScript 라이브러리
* **Next.js:** React 기반 웹서비스 개발 프레임워크
* **Vercel:** 웹사이트 배포와 호스팅을 제공하는 플랫폼

---

## 8. 웹 개발의 기본 구성

* **Frontend:** 사용자가 보는 화면과 상호작용 처리
* **Backend:** 서버 로직, API, 인증, 데이터 처리
* **Database:** 서비스 데이터를 저장하고 관리

현재 실습 구성:

* Frontend: Next.js
* Backend: Node.js 또는 FastAPI
* Database: Supabase

> AWS는 데이터베이스가 아니라 다양한 인프라를 제공하는 클라우드 서비스이다.

---

## 9. 데이터베이스 종류

* **RDB:** 데이터를 테이블과 관계 중심으로 저장
* **NoSQL:** 문서, 키-값 등 다양한 형태로 데이터를 저장

대표 예시:

* RDB: MySQL, Oracle, PostgreSQL, SQLite
* NoSQL: MongoDB, Redis

---

## 10. CRUD

* **Create:** 데이터 생성
* **Read:** 데이터 조회
* **Update:** 데이터 수정
* **Delete:** 데이터 삭제

---

## 11. AI Agent의 대화 기억

* AI Agent의 대화 기억은 필수가 아니라 선택 기능이다.
* 대화 기록은 RDB와 NoSQL 모두에 저장할 수 있다.
* 핵심은 저장소 종류보다 어떤 정보를 LLM에 다시 전달할지 설계하는 것이다.
* 토큰 사용량, 요약 범위, 개인정보 보관 기간을 함께 고려해야 한다.

---

## 12. 오늘의 핵심 요약

* 좋은 기획서는 목표, 범위, 조사, 리스크 대응이 명확해야 한다.
* 웹 렌더링 방식은 페이지 목적에 따라 선택한다.
* 현대적인 웹서비스는 여러 렌더링 방식을 조합한다.
* 웹서비스는 프론트엔드, 백엔드, 데이터베이스로 구성된다.
* AI Agent 기억 설계에서는 토큰과 컨텍스트 관리가 중요하다.
